## 复现入口

从仓库根目录运行（先安装 `requirements.lock.txt`、`requirements-eqgpt.lock.txt`所需依赖）：

```bash
# 方案一上游：先查看实际参数，按 protocol.json 的配置运行
PYTHONPATH=.:src python scripts/evaluate_screened_pde.py --help
# 方案一下游：按各案例 protocol.json 运行；此命令显示参数而不启动训练
PYTHONPATH=.:src python scripts/eqgpt/fast_reward_case.py --help
# 方案二上游
PYTHONPATH=.:src python scripts/run_upstream_811.py
# 方案二下游：从已保存权重/结果恢复时会校验并复用
PYTHONPATH=.:src python scripts/eqgpt/run_expanded_all_cases.py --device mps
```

`--help`是参数查看，不代表已经重跑或验证整套结果。完整下游运行会训练、搜索，常规结果查看不需要运行。已有权重的下载与使用见各Release和 `scripts/eqgpt/README_权重.md`、`experiments/expanded_downstream_80_v1/README.md`。

## 中间材料与历史边界

- `data/formulas/expanded_downstream_v2/`是方案二全量准备池，80容量准备脚本依赖其词表；不是第三套正式实验。
- `data/formulas/gre_benchmark_merged/`是早期外部与1500条通过分量的合并资源；它不是本次2045条新外部benchmark。为保留来源核查链而保留，不作为任一正式训练入口。
- `reports/preparation_811/`的GRE首轮转换结论、`reports/gre_benchmark/`的早期统计是带阶段标识的历史证据；最终下游数量由80子集manifest确定。
- 本地废弃的 `expanded_downstream_v1/`（GRE重渲染稿）、两个 `expanded_downstream_smoke*`、旧PDF构建临时产物不作为正式实验提交；保留在本地且不删除。
- 远端三个分支及两份Release本次保留；本次不删除历史分支、不重写历史。主分支合并另行确认。

## 三轮交付检查

```bash
PYTHONPATH=.:src python scripts/verify_two_studies.py --round 1
PYTHONPATH=.:src python scripts/verify_two_studies.py --round 2
PYTHONPATH=.:src python scripts/verify_two_studies.py --round 3
```

第一轮检查代码测试；第二轮独立核验上游划分、78配置、逐公式指标、冻结选择与测试，以及两套下游候选/权重绑定；第三轮检查Git交付清单、文档链接与远端分支/Release。核验报告保存在 `reports/repository_two_studies/`，发现问题时修正后重新运行。
