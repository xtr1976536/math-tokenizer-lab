# 本轮两次检查：树形网页、指标、完整 EqGPT 与权重

## 第一轮：本地文件与运行

- 网页新增**训练规则树、公式 AST/语法绑定树、token 解码树**三个视图。训练视图展示冻结词表的规则分解；当时没有保存每轮全语料候选频率，网页没有编造这部分历史。
- 桌面和手机分别检查了公式选择、输入、三个词表切换、逐步合并及三个树视图；无浏览器异常和横向溢出。离线 `file://` 加载通过，页面无需外部字体、统计脚本或数据接口。
- 浏览器在 100 条 benchmark 公式 × 3 个词表上的最终 token ID 与 Python 实现 **300/300 一致**。自定义公式的结构区间与原生前端一致。
- 上游三指标统一显示为 `tokenizer compression`、`operation`、`numbers`；历史结果的数值和机器复核字段未重新计算。
- `third_party/eqgpt/code/` 保留原论文的完整训练、搜索、surrogate、reward、`PINN_optimization.py`；与 `scripts/eqgpt/fast_reward_case.py` 的 3 层快速实验分开。
- 八个 MLP 最终缓存及原始数据在私有 Git 仓库内。4 组共享预训练权重和 32 组搜索后权重逐一通过训练/搜索记录中的张量哈希校验。
- 直接加载脚本在 Wave 上实测 `generate`、`score` 与小预算 `search`；新案例模式可以加载共享预训练模型生成结构，但新数据的 reward 仍需拟合相应 surrogate。

## 第二轮：远端发布

- 私有仓库 GitHub Release `eqgpt-fast-20261022-weights-v1` 共 **36 个资产**。远端每个资产的名称、字节大小和 GitHub SHA-256 均与 `benchmark/weights_manifest.json` 一致；另从远端实际下载 350-ID 预训练权重并重新计算 SHA-256。
- 网页在单独的**公开** GitHub Pages 仓库 `xtr1976536/ast-bpe-visualizer` 发布，地址为 `https://xtr1976536.github.io/ast-bpe-visualizer/`，HTTPS 强制开启；私有研究仓库仍保持私有。
- 公开网页仅包含静态源、三个词表与 1500 条公式的展示字段及来源链接；不包含八案例原始数据、MLP 缓存、Transformer 权重或私有日志。公式选中后展示论文题名、arXiv 链接及来源记录的许可状态，多数许可状态仍未确认。
- 发布后重新从 GitHub 远端核对文件树、权重 Release 与网页实际交互，记录提交哈希和页面状态。

可在仓库运行 `python scripts/检查仓库.py` 重做结构化内容检查。这里的八案例仍为已知 PDE 回收实验，不包含新的未知方程数据 benchmark。
