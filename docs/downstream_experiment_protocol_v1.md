# 数学公式分词器的下游实验协议（研究设计 v1）

状态：设计完成，尚未生成任务数据或训练下游模型。阶段二自主分词研究继续暂停。本协议只使用 `models/registry.json` 中冻结的两个自研分词器和五个基准；主实验使用 `broad-2048` 检查点，`broad-1024` 是容量敏感性实验。任何容量或场景切换须在查看任务测试集之前登记。

## 1. 核心问题与证据边界

要回答的是：在**同一个数学任务、同一批原始题目、同一模型主体和同一训练协议**下，改变公式的分词方式是否改善数学正确率、PDE 数值精度、跨类型泛化和达到这些质量所需的计算量。现有公式库是分词器训练与内在评测材料；它只有公式，不含下游监督标签或 PDE 解场，不能当作下游任务数据。

第一层实验从随机初始化的共同模型训练七个版本，可以比较分词器方案。自研 AST 边界与数学原子 BPE 在对应容量下共享词表和 ID，这一对比最接近隔离“切分规则”的效应。第二层实验将新分词器接入同一个开源小型预训练模型，评价迁移的工程代价；原生分词器加原权重模型作为必需的锚点。第二层涉及新词嵌入初始化和已有权重的偏好，不能用来单独证明分词算法优越。

五个固定基准是 byte BPE、SentencePiece Unigram、Qwen2.5、Llama 3、o200k。七者都参加**相同的四项任务、相同题目和相同评价程序**。前三个通用预训练词表的真实规模远大于 2048，需单列总参数量、输出层参数和计算成本；不得把它们称为“等词表对照”。

## 3. 四项核心任务

### A. 符号积分

输入 LaTeX 被积函数，输出一个原函数。分别抽取前向生成、反向求导生成、分部积分生成三层，避免只在一种合成分布上成功。主指标是 top-1 **微分验证通过率**：解析输出 `F`，验证 `dF/dx=f`。符号化简未能判定时，数值点检查只用于诊断和寻找反例；未获得解析证书的答案记作“未证实”，在主指标中计失败并单列。解析失败、超时、非法 LaTeX 均计失败，单列失败类型。附报 pass@10（固定 10 个候选）、公式有效率、每题推理时间。字符串精确匹配只作诊断。

### B. 一阶 ODE 求解

输入一阶 ODE 和初始条件，输出满足初值的解；先限定 Lample–Charton 生成器支持且独立验证器可判定的函数族。主指标是 top-1 **代回微分方程和初值同时通过率**。附报 pass@10、残差分布、有效率。二阶 ODE 是难度扩展，只有一阶任务通过可行性门槛后再冻结数据并启用。没有初值的通解有任意常数歧义，不用于初版主指标。

### C. 公式条件下的 PDE 正向预测

输入可变的 LaTeX 控制方程 `u_t=...`、初始场和边界条件；方程系数只在公式里出现，数值通道不提供重复的系数或 PDE 家族标签。在指定 `(x,t)` 查询点预测**连续数值** `u(x,t)`，使用统一数值编码器和连续输出头。这是最直接的“给出 PDE 并求解”设置；额外提供前几个观测时刻的 PROSE 式设置作为敏感性实验。候选家族为一维平流、扩散、Burgers、反应扩散；是否全部纳入以共同难度试点确定。每个家族必须有多个系数、初值和公式实例，避免方程文本成为常量。主指标按**方程家族先平均，再跨家族平均**的归一化 RMSE 或相对 L2；每类分别报告。归一化分母与近零场的处理方式在测试前冻结。附报未来时间段误差、边界/初值误差、R²、推理耗时。仅在稳定、高分辨率参考解可得时报告 PDE 残差；残差的数值差分误差先用参考解校准。

必须有“遮去方程文本”的消融；若遮去后预测不变，这项任务不能支持“公式分词有用”的论断。PROSE-PDE 的符号加数值条件与 PDEBench 的数值评测提供设计依据，但本项目的缩小设置不与其论文分数横向比较。

### D. 带部分方程信息的 PDE 恢复

输入短轨迹和含缺失算子或系数的 LaTeX 方程骨架，输出完整方程。例如在同一候选集合内恢复扩散项、对流项及系数。候选算子集合与缺失位置必须平衡，骨架不能把正确算子或系数编码在占位符里。数值观测通道与任务 C 一致，输出由共同的公式模型生成。主指标是**算子结构恢复率**；系数估计报相对误差，并用恢复方程在未见初值下求解的轨迹误差确认物理等价。另报解析有效率、预测轨迹误差。纯数值到方程恢复可作为输出端分词的附属实验，清楚标注其输入端没有公式可供分词。

## 4. 数据划分与泛化

使用公开生成器与数值求解器产生**新任务样本**，不修改当前公式语料。任务 A/B 按表达式树模板与规范化表达式分组，而不是按随机样本行划分；同一个积分原函数的代数等价形式归入同组。任务 C/D 按方程实例、系数区间和初始条件生成种子分组，绝不把同一条数值轨迹的不同时间窗分到训练与测试。所有模型共用原始题目清单、LaTeX 渲染器、参考数值场、切分文件及评价器。保存生成器版本、随机种子、渲染规则和样本哈希。

固定四层测试：①同家族但新模板/新初值；②未见系数区间或更长公式；③预先选定一个未见 PDE 家族或跨符号领域；④同时改变家族与初值的极端泛化。③④单独报告，不与同分布主分数混成一个掩盖失败的平均值。对未见家族，训练数据不能出现该家族的同义改写。另用未参与生成器调参的 PDEBench 原始数值样本做**外部测试**，只选方程、边界和网格可以被本任务统一表示的子集，公开筛选规则。任何分词器训练语料、继续预训练语料和任务训练数据与最终测试题目做规范化公式、树模板及轨迹 ID 的污染审计；只承诺可检出的重合层次，不宣称语义上绝对无污染。

试点规模建议：每项约 2,000 训练 / 200 验证题，测试集封存不用；所有七个版本跑通且任务不出现普遍 0% 或接近 100% 后，在测试前固定正式规模。正式初始预算建议 A/B 各约 20,000–50,000 训练题，C/D 各约 10,000–20,000 条**独立轨迹**，每项至少 2,000 个测试题或轨迹；PDE 家族数量、复杂度层与 OOD 层按足够样本的家族配额预先平衡。样本数只是本机可行性的起始值，最终上限以公开的算力试点测量决定，不能依据任何模型测试分数调节。所有实验规模和生成范围先冻结后使用测试集。

## 5. 模型、训练与公平比较

同一任务的七种分词器使用相同数学题目、数据顺序、随机种子、Transformer 主体、连续数值分支、优化器、学习率搜索空间与开发集选择规则。符号任务采用共同的小型序列生成 Transformer；C 使用相同公式编码主体、数值观测编码器和查询点连续解码头；D 在此基础上使用相同公式生成头。模型配置应在单机 Apple Silicon 16 GB 的统一显存可行性试点后冻结。大词表会增加嵌入和 softmax 参数，始终同时报告**主体参数、总参数、峰值内存、训练 FLOPs/设备时间**。不能在主表中把 200k 词表和 2k 词表称为严格参数匹配。

**数据量匹配**是主实验：相同原始问题、批次顺序、训练例次与最大原始 LaTeX 长度；记录每个分词器实际 token 数及计算量。不同切分造成的每例算力差异本身是成本结果。**计算量匹配**为第二视角：沿同一训练曲线，在预先设定的近似相同训练 FLOPs 档位比较质量，同时报告各模型实际见过的原始题数。仅匹配 token 步数会导致原始题目暴露量不同，不作为唯一公平标准。精度、总成本、质量达到固定阈值所需时间各单列，不强行合成一个综合排名。

控制输入覆盖：对所有模型先按共同的原始题目长度条件筛选；预设能容纳全部入选题目的 token 上限，若显存不足，只能**共同缩小任务原始长度范围**，不能对某个分词器额外丢弃难题。输出限额按原始答案复杂度和统一候选数设置，记录因 token 上限导致的截断。统一 BOS/EOS/PAD 与任务控制符的语义和计数，记录它们对词表大小的影响。数学检验器、beam 候选数、求解器精度与超时在所有模型间共用。主指标基于解析/数值有效解，不直接比较每 token 交叉熵；若附报概率量，标为“给定分词序列每源字节编码长度”。

优化器步数相同并不必然使训练 FLOPs 相同。对所有任务至少用 3 个独立训练种子复验，配对的测试题用同一组；报告均值、标准差或区间，以及按表达式模板/轨迹分组的配对 bootstrap 95% 区间。预先定义各任务主指标和多重比较修正，先看自研两者相互比较及相对五基准的区间，再看辅助指标。禁止通过测试集选择 checkpoint、难度层或渲染器。

最关键的归因消融：① AST 边界与数学原子 BPE 的同 ID 词表成对比较；② PDE 输入遮去或打乱方程文本；③ D 的输入骨架遮去；④ 仅对同 ID 自研词表，交叉组合输入切分和输出切分，判断收益发生在公式读取还是公式生成。以上消融不改变题目或评价器。

## 6. 预训练接入与执行顺序

主实验完成后，选一款约 100–150M 参数、在本机能承担的开源小模型作为共同权重底座，保留其原生 tokenizer 版本；给两个自研 tokenizer 和五基准替换嵌入/输出层并做相同原始数据量和计算量的继续训练。新 token 嵌入至少比较基于旧 token 分解的对齐初始化与随机初始化，保持相同适配预算；与“原生词表 + 原模型继续训练”对照。此实验回答**接入是否值得**，不能与随机初始化七方主实验混为同一排名。若 16 GB 试点不支持全模型参数更新，可用共同的嵌入更新加相同 LoRA 范围，明确哪些原权重冻结。适配策略对七者完全一致；原生模型保留其原词表的对照身份。

执行门槛依次是：冻结生成器/渲染器/评估器 → 七种分词器都参加同一小试点并校准任务难度与 16 GB 内存配置 → 七种分词器同样四任务、同数据量主实验 → 三种子复验与 OOD → FLOPs 视角、消融、预训练接入。试点选择统一任务难度和模型配置时只看开发集，不接触封存测试集。最终表格对每个任务分列主指标、OOD、置信区间、总参数与计算成本。若某项任务所有模型都处于地板或天花板区间，标为“无区分力”，不计胜负；跨任务不做未经论证的加权总分。

正式结果前执行四轮独立审查：第一轮核对生成器、参考解、分组划分和污染；第二轮核对七个 tokenizer 的同题输入、覆盖率、特殊 token、模型主体与训练日志；第三轮核对数学验证器、数值求解器精度、超时和统计脚本；第四轮从冻结配置重跑代表样本及至少一整个种子，比较逐题结果和汇总表。每轮保留机器可读审查记录，发现问题时先修复并重新运行受影响的全部七个模型，再做结论。

CodePDE 的可执行代码生成、严格数值求解与 `nRMSE` 很有价值，但小模型在本地生成完整稳健求解器可能普遍失败；其任务还加入编程能力和执行环境因素。因此先不进入核心四项排名。若试点至少有两个分词器产生非零成功率，才冻结相同五 PDE 家族、相同代码执行容器和相同每题采样预算，作为扩展实验。通用自然语言数学题和定理证明的文本因素较大、算力门槛较高，待公式任务获得可靠因果证据后再评估。
