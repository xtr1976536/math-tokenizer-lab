# 全实验回溯：模型分类、条件排名与优劣分析

审计日期：2026-10-11；被审计代码与实验基准：`e2db11c`。本轮暂停研究推进，只读取既有源码、模型、配置、dev消融和测试结果；没有重训、重新编码、调奖励、修改语料或模型。`scripts/all_model_review.py` 独立核对 **9个正式目录、216条方法/种子/场景记录、563,399条逐公式结果**。216不是216次独立训练，563,399也不是563,399条不同公式。

全部方法/版本的数值见 [数值附录](all_model_review_numeric_appendix.md)；按领域、来源、复杂度及stress类型独立重算的统计与原始文件哈希见 `results/retrospective/all_model_inventory.json`。v1—v4机制及初始化学习核验见 [前次技术路线审计](technical_route_retrospective.md)。

## 先给判断

目前没有一个模型同时在速度、压缩、结构、泛化、低人工干预以及RL独立贡献上获胜。综合评价必须保留三个不同用途的领先方案：

| 优先目标 | 目前领先方案 | 结论的性质 |
|---|---|---|
| 快速编码、较少手工数学规则、多指标词表设计 | v5复合奖励贪心控制与v5 RL词表模型 | 贪心在自然公式总体压缩/命令完整性上点估计领先；RL达到普通BPE速度量级，但未证明超越贪心 |
| 尽量短，同时较好保留命令 | v3 RL压缩分支；同词表非RL shortest更短 | 旧固定测试上自研RL版本中最短；保留跨树问题，约1.15MiB/s |
| 硬结构合法、命令完整 | v4非RL AST/Grammar-BPE | 旧测试99.52%命令完整、可解析部分零crossing；v4 RL没有额外部署压缩优势 |

这是按用途给出的选择，不是跨语料的无条件总排名。若限定“我们提出的方法”并把用户最近强调的**速度、少手工规则、核心指标**作为优先级，v5 RL是当前最合适的RL主分支；若把硬结构完整放在第一位，则v4 AST是最合适的结构分支。二者目前都不能替代另一条路线。

## 一、所有方法应怎样分类

### 1. 经典及成熟基准

| 方法 | 训练/实现 | 优势 | 局限 |
|---|---|---|---|
| 自研byte BPE、官方HF ByteLevel BPE | 频率选merge，固定预算；HF使用原版Rust | 稳定、训练快、部署简单；无regex预切分版本适合直接研究公式串 | 不主动保留数学边界；两者分词长度相同不表示速度相同 |
| SentencePiece BPE | 原版实现；identity、无dummy prefix、byte fallback等无损配置 | 快于本轮HF/RL；训练成本低 | 当前配置命令内部会切边界，命令完整率为0%；不表示其下游能力为0 |
| SentencePiece Unigram | 原版概率词表模型 | 本轮自然公式速度领先，数字完整性略好 | 自然公式压缩较差，命令碎片；不是各项指标都差 |
| GPT-2/cl100k/o200k/Qwen2.5官方tokenizer | 固定预训练词表，不用本项目数据训练 | 稳定公开接口、真实部署参照 | 词表大小、预训练数据与预切分规则不同，不能进入同预算训练算法排名 |
| UTF-8 bytes | 每字节一个ID，256项 | 极快、保证fallback、便于检查 | 公式长，命令碎片；其零crossing不能单独当质量优势 |

固定预训练组的GPT-2、Qwen只在v1/v2正式测试中跑过，本轮没有假定它们在v5仍维持旧排名。cl100k/o200k在v5新论文分别31.1159/30.7191 token/公式、10.0638/13.2376MiB/s；它们是使用效果参照，不证明小预算方法的训练算法优于所有大模型分词器。

### 2. AST/结构路线

| 版本 | 实际机制 | 目标及收益 | 主要缺点 |
|---|---|---|---|
| AST-v1 | 受限semantic AST的源跨度约束byte-BPE；失败整式bytes | 源串完全可还原、解析子集零crossing | 覆盖差，旧扩充测试接近byte长度，已经明显落后 |
| AST-v2 | semantic AST +显式LaTeX CST回退、ranked BPE | 解决大量解析失败，压缩比v1好得多 | CST不是数学语义；缺命令原子，速度及压缩仍落后 |
| AST-v3 | train抽取命令原子+结构BPE+受约束shortest+C前端 | 命令96.50%、零crossing；512预算的结构方法中更短 | parser规则依赖，约1.17MiB/s；不是原始AST节点序列BPE |
| AST-v4 / Grammar-BPE | 更强command/codepoint原子及hard tree mask，shortest解码 | 命令99.52%、零crossing；1024预算略短于v3 | 稀有原子占预算，512明显变长；仍有未知单位byte escape |

所有版本保留原LaTeX源串，尚未完成“通用语义AST节点化→节点/子树BPE”的原始提案。树指标与编码约束共用本项目parser，没有独立黄金语义树，所以零crossing只证明相对这些源跨度的合法性。

### 3. RL路线与融合路线

| 版本 | RL到底学什么 | 优势 | 未解决的问题 |
|---|---|---|---|
| RL-v1 | 在top24候选中学选下一merge；4参数一步REINFORCE | 离线学表、在线标准BPE思路早期原型 | 主要立即压缩收益，未稳定胜过BPE；长期规划未实现 |
| RL-v2 | 固定词表上学完整分词路径；7参数、REINFORCE/RLOO | 对相同初始化有小幅压缩改善；训练降低方差有证据 | 固定词表shortest更短；Python推断约0.09MiB/s |
| RL-v3 | 原子固定词表上学路径，soft tree penalty，C推断 | 旧测试RL压缩最好，命令完整性高；约12倍旧Python速度 | 跨树仍13.17%/18.18%；收益混合了词表、解码、工程与RL |
| RL-v4 | 结构合法DAG上精确期望cost策略梯度；7参数 | 真实策略学习且cost主项有限差分通过；硬零crossing | 规则来自mask；随机期望目标与MAP/greedy部署错位，1024未胜初始化 |
| RL-v5 | 离线merge/词表策略；11参数、全期望contextual bandit更新、复合reward；导出官方Rust BPE | 在线不跑policy/parser，8.68MiB/s；新论文多项指标改善，手工结构规则更少 | 仍是立即收益，候选收益可全部计算，贪心很强；新paper crossing26.22% |
| RL-AST-v1/v2/v3 | 合法merge或路径中学选择，外部AST/CST提供合法性 | 结构可控、无需逐式分词标注 | 没有胜过同词表非RL最短路径；v4已与严格RL主分支合流 |

v5的奖励同时考虑压缩、heldout unigram code-cost代理、词法边界、稀有暴露、空白变体收益一致性。code-cost不是LM BPB；词法保存不是数学推理。通用lexer、奖励权重、候选、特征、预算、dev选择规则仍是人工设计，不能称完全无人介入。正式v5的不同seed产生相同merge/分词，是确定性重复，不是三次独立证据。

### 4. 控制、探索及工程版本

- **因果归因控制**：相同fit BPE、frequency/random/reward-greedy、same-vocab shortest、相同初始化no-update、zero policy、仅加mask、纯长度reward。它们必须进入相应比较，不能只排提出的模型而隐藏更好的控制。
- **未选主模型的探索**：大BPE seed词表的path-usage修剪、RL token swap；只有dev试验，改善小且不一致，不能当验证成功的方法。full-train pruning在512为18.7240/18.8113、1024为15.1531/15.5687 dev token/公式；swap小样本byte18.3611→18.2945，AST18.9306→18.9840。
- **训练估计器研究**：naive、RLOO、relative、discount、entropy、expected等是同路线的配置/消融。v2固定策略32式/128batch probe中RLOO平均坐标方差0.000264、naive0.020705，支持方差降低，不证明最终tokenizer质量优于全部方法。
- **等价工程加速**：增量merge索引、堆、原生C DP、等价fast parser、native-exact旧checkpoint。输出相同者只算一种质量模型；速度改良单独记录。v5则改变了学习对象与部署路径，不能称同一个v4模型纯代码加速。

正式dev扫参也全部列入机器清单，共382条评测记录；不能把它们混入test排名，或当成382次独立训练：

| dev实验 | 每预算/阶段评测行 | 评测对象及计数限制 |
|---|---:|---|
| v2，512/1024各一套 | 38 | byte/AST的naive/RLOO/relative、discount、entropy、更新数/初始化等；train-only奖励，dev选配置 |
| v3，512/1024各一套 | 80 | 5个AST原子预算、3个非RL控制、24次策略训练各测3种cross penalty；不是80次训练 |
| v4，512/1024各一套 | 63 | 3个AST预算、30次策略训练各测greedy/MAP；不是此前措辞所称123行/预算 |
| v5，两训练场景合计 | 20 | 每场景4个复合reward+1个纯长度消融，各2seed；配置由dev选定 |

预发布失效dev记录同样保留路径、哈希和结果摘要，但在清单标为非正式。每行配置、指标及训练日志条数可直接在审计JSON查询，不以最好的dev数字冒充泛化结果。

v5 RL、frequency、random、greedy使用相同至多6000式fit；RL/greedy还利用train内部独立384式reward。HF matched-fit只见fit，HF full-train见全部场景train，SP也见场景train。相同测试/预算/公共评测接口成立，实际训练公式曝光并非所有方法完全一致；full/fit控制各回答不同问题，不能称纯RL单因素实验。

最初406式pilot也没有被跳过：384下byte/HF14.3768、RL14.4787、AST17.5369、RL-AST17.6437；512下RL12.5320、byte/HF12.6158、AST16.8177、RL-AST16.8432。早期RL在512略优、384略差，结构coverage仅48.8%；单看512就宣布RL稳定优于BPE会过度解读。

## 五、泛化和极端样本会改变排名

### 1. 分领域结果不是全部向好

新论文broad测试中，RL比HF full在11/13个公式领域的token/公式点估计更低，logic为10.3261 vs9.7174、number theory为14.8144 vs14.6014，反而更长；很多领域仅1—4篇论文。simple为11.8789 vs12.1470，complex为46.4683 vs48.0892，均点估计更短；但complex仍不如greedy45.8241，simple与greedy11.8888很接近。

真正specialized域迁移的全部五域如下：

| 领域 | 公式/论文组 | RL token/公式 | greedy | random | HF full |
|---|---|---:|---:|---:|---:|
| algebra | 327/3 | 15.8043 | 15.7859 | 16.1498 | 15.8685 |
| combinatorics | 472/4 | 15.0064 | 15.0424 | 15.0106 | 15.5275 |
| geometry/topology | 500/4 | 16.5280 | 16.2940 | 16.3540 | 16.4180 |
| logic | 46/1 | 10.8913 | 10.6957 | 11.0000 | 10.8478 |
| number theory | 291/2 | 15.4227 | 15.3230 | 15.1924 | 15.4021 |

RL仅代数/组合的点估计短于HF full，几何/逻辑/数论略差；总均值主要受组合改善影响。样本量小、同文档相关且领域标签自动生成，不做逐域显著优劣宣判。来源分层也与领域/长度混杂，不把human/mixed/AI桶的差异归因于生成来源。

### 2. synthetic stress不能并入自然公式平均数

| 场景 | 最短候选的点估计顺序 | 关键反例 |
|---|---|---|
| broad，693式 | greedy102.1443 → RL102.9149 ≈ HF full102.9221 → length103.4719 → fit/frequency103.5440 | RL与HF几乎同长，不能说普遍极端压缩优势 |
| specialized，693式 | HF full108.0361 → fit/frequency109.1039 → length109.1241 → RL109.2973 → greedy112.7316 | RL较HF约长1.17%；greedy自然公式的领先没有延续 |

机械最长样本2048项/71507字节，RL31820 vsHF31582 token；深256层两者769；8193字节巨大数字两者8192；未知macro/Unicode两者39；损坏TeX两者3。全部100%无损，但这只是fallback/解码健壮性，不证明坏TeX有语义或数值推理更好。平均token/公式受极长样本影响，审计JSON中的分stress tokens/byte应一起看。

冻结v3/v4对fresh论文为21.1273/23.2439，命令98.46%/99.96%，速度1.401/1.315MiB/s；说明旧v3仍短、旧v4仍严。它们训练集不同，不能据此宣称v5训练算法退步或提升；v3/v4目标域13.9334/15.0966更不能与专用模型混排成真正OOD冠军。

## 六、哪些改进真正可归因于RL

| 证据强弱 | 已有证据 | 能得出的结论 |
|---|---|---|
| 强：工程等价 | C/fast parser逐token/跨度核对；v3旧RL native约12倍Python速度 | 工程提速有效，不能归因于RL分词质量 |
| 强：结构设计 | coverage回退、原子词表、hard masks；同词表shortest控制 | 边界与覆盖设计有效；零crossing是规则保证 |
| 中：复合目标 | v5对length-only新论文长度/命令指标较好，压缩CI不跨0 | 只奖励短序列不足；多目标设计有价值 |
| 中：真实策略学习 | v2相同初始化约0.4%压缩改善；v4成本梯度/训练期望降低 | 并非没有RL学习，但部署增益小或未转化 |
| 弱：RL优于强非RL控制 | v3 shortest更短；v4 shortest/初始化不差；v5greedy点估计更好 | RL独立价值仍未充分建立 |
| 未建立 | 通用semantic AST、无人介入、长期词表规划、下游数学能力 | 现有实验没有支持这些完成声明 |

v4固定同一768式train子集的matched initial→trained期望token：512为20.7751→19.0664；1024为15.5980→13.8947。随机目标确实改善，但1024 dev只有19/2808式确定性分词改变，test训练后14.9462略长于初始化14.9437。v4 zero-init weak control不能代替shortest强控制。

v5只在有限merge候选上使用立即收益，特征直接含这些收益分量，11参数策略并未学到未经观测的长期合并价值。reward-greedy的存在说明已有改善很可能主要来自奖励与候选设计，而不是已经验证的长期RL规划。这不否定RL研究潜力，但必须把“路线有前景”与“目前优势已证实”分开。

## 七、排名的可信边界与归档范围

1. 本次重算验证输入IDs一致、总token/byte、无损率、命令/数字/词法完整与tree-crossing一致，并验证manifest模型/配置哈希及v2/v5 corpus哈希。没有重跑模型，更没有以本轮test改参数。
2. 旧test在v2—v4开发中多轮可见，只能作重复benchmark比较；v5首次新test在selection前封存，证据更强，但现在也已经暴露。来源许可/版本审查、paper隔离、词法模板去重不等于数学语义等价去重或专家gold标签。
3. 所有正式记录100%还原是底线，不是优秀程度的区分指标。命令、树、熵、词表利用率、经验编码量之间有取舍；entropy/利用率也不是一味越高越好。旧版TokEval上下文熵结果保留在原目录，不将缺覆盖的指标强行补成统一排名。
4. 速度是保存的同接口稳态encode结果，不包括加载/首次编译，不等于全部训练成本。HF训练约0.52秒、v5 RL约9秒（broad正式记录），离线训练仍较慢；跨v2-v4 train_seconds常有vocab/policy统计口径差异，不能直接排总训练成本。
5. 统计区间按文档/家族bootstrap1000次，条件于既定训练与语料，没有把三次确定性seed当扩大样本，也不把多项未校正比较当强因果结论。少量论文的领域子表是描述性结果。
6. `smoke01`、`v2_smoke512`只验可运行；`v2_512`、`v2_512_final`、`v2_1024_final`、`v3_512`是不完整或后来失效的预发布记录；variance/native/pruning/swap是探索或实现核验。它们都被归档、分类，但没有用来争正式测试名次。
7. 过去六轮/多轮工程检查、v1/v2全新环境训练复现、v3-v5 checkpoint重放及最新141项测试均有记录。后者不是全部候选在独立环境重新训练，也不是跨硬件复现或外部同行审核。

截至本轮，最稳固的研究成果是**可审计的公式benchmark、结构/原子分词设计、成熟BPE速度的离线词表部署，以及对RL独立贡献的强控制**。最需要保留的不利证据是：v5没有胜过greedy，v4严格规则压缩有代价，极端域/机械stress没有统一胜出，尚无下游性能证据。本次只完成分类与回溯，研究继续保持暂停。
