# GPT-2 下游实验：符号积分与 ODE

状态：本机只运行烟雾测试；正式数据、八组全参数训练和封存测试都在私有 Kaggle 作业上运行。本文件记录实际实现，结果只有在全部作业和审查完成后才发布。

## 任务与数据

数据源是 `facebookresearch/SymbolicMathematics@4596d070e1a9a1c2239c923d7d68fda577c8c007`（CC BY-NC 4.0）。积分使用原仓库的 FWD、BWD、IBP 生成器各 8,000 道训练题。一阶 ODE 使用论文的“构造含常数的解析解并消去常数”方法，但限制为 `y(x,c)=c*g(x)+h(x)`：`g,h` 仍由固定版本的原仓库表达式生成器产生。这个受限分支避免了旧 `sympy.solve` 在当前 SymPy 版本上长时间卡住；所得分布不应称为论文原始 ODE1 数据集。ODE 有论文式方程到解、方程加初值到特解两个视图，各 12,000 道训练题。验证和测试配额见 `data.py` 的 `QUOTAS`。

所有原始表达式统一由 SymPy 渲染为 LaTeX，乘法显式写作 `\cdot`，避免解析器把 `x(x+1)` 读成函数调用。生成时保留上游前缀式与独立方程组 ID；同一 ODE 的两个视图必须同组划分。额外的长式测试采用变量变换 `x -> x^3+x+1`，要求题目长度超过对应训练分布的 90 分位；未见组合测试采用 `x -> exp(sin(x))`，并从常规训练/测试中共同排除该组合。两者都重新验证数学答案。

## 模型与评价

共同底座是 `openai-community/gpt2@607a30d783dfa663caf39e06633721c8d4cfcd7e`。七个冻结候选使用 `broad-2048`（大模型原生词表保持完整），另外加入原生 GPT-2 分词作接入校准，校准行不进入七方排名。保留 GPT-2 的 Transformer 和位置嵌入，按目标词表更换绑定的输入/输出嵌入。目标 token 按原始字节精确分解为 GPT-2 旧 token，用字节长度加权的旧嵌入初始化。AST 边界与数学原子 BPE 的字典与 ID 相同，初始化文件哈希必须一致。保留特殊 ID 不参与公式输出；任务标记和结束符统一新增。

八组统一全参数微调 3 轮，种子 11/23/37，有效批量 32，主体学习率 `2e-5`、新嵌入学习率 `2e-4`，AdamW、5% 预热、梯度裁剪 1.0。损失先按每道题的答案 token 平均，再按原始题目平均。主检查点按验证集积分三生成方式的平均正确率与带初值 ODE 正确率等权选取；若正确率相同，用预固定的验证子集答案损失打破平局。相同原始题目的输入必须被八个分词器共同覆盖，不能按模型单独删题。

积分的正确性由求导检验；ODE 解代回方程，初值视图还需满足初值。未证明正确的答案不计成功。封存测试使用贪心 top-1；固定分层子集另报 beam-10 至少一解正确率。输出逐题文本、验证状态、无效率、分任务和 OOD 成绩、参数量、训练时间、内存采样值，并做按方程组配对的置信区间。微型烟雾测试中的零正确率不构成模型结论。

## Kaggle 作业顺序

1. 本机完成四轮代码/协议审查与额外打包检查，上传不含原始公式库的私有资源集。资源包只携带公式标准化 SHA-256 哈希以审计可检测重合。
2. Kaggle GPU 烟雾作业测试八组环境、嵌入、优化和重载。Kaggle CPU 作业并行生成正式积分/ODE，封存数据，验证全部参考答案，生成两类 OOD 和共同覆盖清单。
3. 八个 Kaggle GPU 作业各训练一个分词器的三个种子。所有训练作业完成后，八个评价作业分别读取本方法三个检查点，最后用 CPU 汇总作业核对测试 ID 和 OOD 哈希、统计配对区间。

上游许可证、GPT-2 权重版本、代码提交、源文件哈希、每次运行配置与四轮审查记录都随结果保存。当前公式库、阶段二实验与既有内在指标不在本轮修改范围。
