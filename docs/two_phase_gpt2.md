# 两阶段 GPT-2 实验

本轮只在本机做烟雾测试并交付两个独立 ZIP。用户手动提交 Kaggle；程序不会自动上传或启动作业。

第一阶段只运行边界 AST、数学原子 BPE、原版 GPT-2。两个自研分词器更换同一预训练 GPT-2 的绑定输入/输出嵌入后，全参数训练 2 轮，种子 11/23/37。原版 GPT-2 的 50,257-ID 原词表及全部原始权重保持不变，只做一次确定性的零样本求解；没有原版 GPT-2 训练作业。它是未接受任务训练的参照，不能把训练后系统对它的优势全部归因于分词器。

第二阶段只运行两种自研方法和 byte BPE、SP Unigram、Qwen2.5、Llama 3、o200k 五个基准。使用官方 `peft==0.21.2` 的 LoRA，rank=8、alpha=16、dropout=0.05，适配 GPT-2 的 c_attn/c_proj/c_fc。新词表的绑定嵌入需更新；其余预训练权重冻结，并检查训练前后 SHA-256。七组均训练 2 轮、相同的原始题目与顺序、相同有效批量 32、相同 LoRA/嵌入学习率 2e-4。三个训练种子沿用 11/23/37。

两阶段共用固定数据生成器、模板组划分、文字提示、原始字节长度筛选、答案解码规则、符号正确性验证、贪心和固定 beam-10 子集、两类 OOD。原版零样本模型收到的是同样可读的文字提示，不能收到未经训练的新增任务标记。取生成的第一行作答案；规则统一且不使用验证器选择后续行。没有 EOS 的答案也会按同一规则检验，截断状态另行报告。

正式数据在 Kaggle CPU 作业产生：积分 FWD/BWD/IBP 各 8,000 训练题，一阶 ODE 12,000 个原方程的普通解/初值解两个视图；覆盖清单按共同字节上限和源库哈希去重后冻结，报告实际使用数量。两个独立包生成同样的数据和覆盖 ID，附带小样本并实际验证离线生成。ODE 生成采用论文方法的线性常数子族，须明确标注而不直接比较原论文成绩。

本地检查至少四轮：配置与单元测试；数据、模板和提示；实际全参数/七组 LoRA 反向传播、保存重载、冻结权重与零样本权重不变；重复运行和题目顺序哈希。最后各从 ZIP 解出的资源再做一次离线数据与训练烟雾测试。烟雾分数不能作为正式结果。

扩大到约 1% 数据规模的检查发现 SymPy 的 LaTeX 解析器会将少数正确的乘积和函数幂误读。数据生成现使用最终数学验证器在入库前复核参考答案，未通过的样本重新生成，并在清单中记录 `oracle_roundtrip` 剔除数。这个规则适用于正式 Kaggle 数据作业。

2026-10-14 的本机预算烟雾测试见 `tmp/phase1_timing/report.json`（只用于资源估算）：约 443 道共同覆盖的训练题、有效批量 32、两轮，按每次更新耗时外推，两个自研方法各三个种子的全参数训练合计约 14.2 小时 M4 时间，LoRA＋新嵌入约 14.4 小时。数据生成、OOD 与审查在约 1% 的串行样本上用了约 176 秒；直接按规模放大约 4.9 小时。正式数据作业会并行生成，且 Kaggle GPU 性能未知，所以这些不是 Kaggle 实测时间。加上正式验证与求解，目前无法确认第一阶段总时长可控制在 4–5 小时；按用户给定的条件，暂不提交 Kaggle。

大词表嵌入和输出 softmax 成本仍存在，所以 LoRA 节约的主要是冻结主干的优化器状态与参数更新；不能保证按 trainable parameter 比例加速。第一阶段结果与第二阶段结果分别统计，原版 GPT-2 的零样本参照不伪造三个训练种子的波动。
