# 分词器下游比较：训练超参数与公平性

日期：2026-10-16。针对 EqGPT 主实验进行定向方法核对；查阅五篇原始论文
的实验设置与附录。它不是声称覆盖所有相关研究的系统综述。

## 文献事实

| 论文 | 原文中的训练控制 | 学习率与参数处理 | 对本项目的启示 |
|---|---|---|---|
| [Dagan et al., ICML 2024](https://proceedings.mlr.press/v235/dagan24a.html) | Table 2 同时报告 500B token-equivalent 和按相同原始字符量对齐的 word-equivalent 结果。 | Appendix H/Table 7 给出共同基础配置；Section 3.1.1 的数据量实验保留其他超参数，只随缩短的数据预算调整学习率日程。 | 相同 token 数和相同原始数据暴露是两种不同的控制；不应混称公平。 |
| [Schmidt et al., EMNLP 2024](https://aclanthology.org/2024.emnlp-main.40/) | Appendix B：约 2M token 的全局 batch，100,000 个 batch，约 200B token。 | 350M 设置共用 LR 3e-4、AdamW、余弦日程和 5% warmup。 | 统一优化配置是已有做法，但不证明该配置对每个 tokenizer 都是最优。 |
| [Lotz et al., ACL 2025](https://aclanthology.org/2025.acl-long.1546/) | 同一 FineWeb 子集训练一轮，数据子集用 100B GPT-2 token 描述；batch 为 2M token，报告不同参数量和 H100 小时。 | 小规模模型依据 pilot 采用共同 peak LR 9e-4；Appendix A/Table 8 给出不同规模的配置。 | 可以先用 pilot 决定合理共享配置。固定原始数据后，计算成本仍可能不同。 |
| [Tao et al., 2024](https://arxiv.org/abs/2407.13623) | 分离词表与非词表参数，用字符衡量数据，并沿 IsoFLOPs 预算比较。 | Appendix A.7.3：共同 peak LR 4e-4，衰减至 4e-5，全局 batch 512。 | 更换词表确实影响参数与成本；既不能忽略成本，也没有“词表一变就必须改 LR”的结论。 |
| [Rust et al., ACL 2021](https://aclanthology.org/2021.acl-long.243/) | Appendix A.5：从零训练的单语模型 1M steps、batch 64、序列长由 128 改为 512；另有单独的 250k-step 嵌入重训练实验。 | 从零训练 warmup 至 1e-4，再线性衰减。 | 区分从零训练和嵌入适配，不能拿后者的设置解释本项目的全参数从零训练。 |

特别核对：Lotz 文中的“cross-validated optimal hyperparameters”脚注对应
预测 tokenizer 排名的 SVM，不是为每个语言模型做单独预训练调参。
该文也明确指出超参数／预训练设置敏感性仍有限制。

原文来源、下载版本 SHA-256、定位与提取事实见 `evidence.json`；引用条目见
`references.bib`。论文提供实验先例，不直接提供本项目的最佳超参数。

## 判断

1. 换词表后必须适配输入嵌入和输出层的 ID 维度；学习率、epoch 不存在随词表规模机械变化的必然关系。
2. 固定配方比较控制优化条件；独立调参比较各方法在同等选择机会下的能力；固定计算比较资源效率。三种问题不能由一个结果同时回答。
3. 等次数的调参不等于等 FLOPs。本主实验记录成本，不声称 IsoFLOPs；额外固定计算实验仍后置。
4. 主实验三个 LaTeX tokenizer 均为 1,024 个总 ID，因而其词表矩阵容量相同。原 EqGPT 的 57 ID、GRE 与 SAT 是系统级参照，不能把二者差异全归因于词表算法。
5. 相同 epoch 应以同一批原始公式定义。不能以 tokenizer 各自的 token 包为“epoch”，也不能截断或筛掉只有部分 tokenizer 无法容纳的公式。

## 本项目采用的训练协议

保留用户确认的两组报告：

- **统一配方**：四种模型均为 Adam、LR 1e-4、100 epoch、每次有效批量 128 条公式、梯度裁剪 1、常数学习率。作者主干与原始代码文件不变。
- **等额验证选择**：每种模型有同样三个 LR 候选 `3e-5 / 1e-4 / 3e-4`，每条轨迹从零训练至 300 epoch，在 100 和 300 处评分，共六个候选设置。LR 日程仍为常数；100 epoch 时不重启优化器。不同模型可以选择不同的最终 LR／epoch。

这组候选值是本项目的工程选择，不是声称文献已证明它们对 EqGPT 最优。
不因某种方法训练失败而单独追加调参机会；失败记录保留。若以后扩展搜索
范围，所有方法采用同样的扩展。

选择规则：

1. 分词器先由允许的独立数学训练分区构建并冻结，不能在 Transformer 的验证分区或下游目标上调整词表。
2. 共同 pilot 先排除全部最终测试目标及其等价结构，再按原始结构分组留出约 10% 验证；所有增强排列和等价重复始终位于同一组。每个方法全局选一组超参数，所有最终案例和种子共用，不能逐个测试目标重新调参。
3. 用唯一原始验证公式的完整序列 NLL 选择该模型的 LR／epoch，不使用最终 PDE 数值数据、发现奖励或测试恢复率。
4. NLL 只在同一个模型／tokenizer 的六个候选间比较，不跨 GRE 和 LaTeX、不同 token 化方式比较原始 token-level CE／perplexity。
5. 选择后冻结训练设置，重新随机初始化，在完整的允许手册训练集上按选定设置训练；最终目标方程继续排除。
6. 正式发现使用既定配对种子 525／526／527。验证选择使用独立 seed 524；原始数据分组固定 seed 20261016。

原论文 100 epoch 设置的结果保留，等额验证选择结果另列；不把二者混成
一张表中的同一训练预算。生成端每轮 400 次尝试、无 SAT、不补采样，继续
训练的 5 epoch／LR1e-5、奖励和 PINN 规则不参与本次超参数搜索。

## 必须记录的成本

每组记录：参数量、原始公式数／字节数、epoch、optimizer step、实际非
PAD token 数、padding 工作量、训练与发现时间、硬件和峰值显存。固定 epoch
不声称等计算；验证调参的总成本和最终重训练成本分别报告。

例：同一批 1,000 条公式，A 平均 20 token、B 平均 60 token。两者训练
100 epoch，都经历 100,000 次原始公式暴露，但分别处理约 2M／6M 内容
 token；它们的计算工作量不同。若反而强行令 token 数相同，原始公式暴露
次数就不同。论文的不同控制方案正是在处理这类取舍。

## 代码落实范围

`training_protocol.py` 固定共同候选与禁止测试指标参与选择的检查；
`validation_selection.py` 调用作者原始训练步执行选择，并在选择后明确要求
重新从零拟合。对应单元测试检查增强分组隔离、候选覆盖、测试指标拒绝和
完整公式 NLL。当前只验证协议模块；独立数学语料冻结接口仍须在正式入口
接通，不能将旧的手册词表 smoke 当作主实验结果。
