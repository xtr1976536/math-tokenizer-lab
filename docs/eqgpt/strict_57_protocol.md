# GRE 57-ID 严格主实验协议

确认日期：2026-10-16。下一次工作按本协议实施，用户计划于 2026-10-17 继续。
当前状态：协议已记录；57-ID 实现、检查与正式运行尚未完成。

## 比较对象

统一使用作者 GRE 结构序列和作者六层 Transformer，从零训练三组：
作者原 GRE 编码、标准硬 AST-BPE、软 AST-BPE。三组总 ID 空间均为 57，
输入嵌入与输出投影均对应 57 个 ID，隐藏维数为 768。

用户确认的六项要求：

1. 不使用完整 UTF-8 字节回退。
2. 新分词器以 GRE 训练文本中实际出现的字符和符号为初始字母表。
3. 在本实验规定的 GRE 字符范围内无损编码。
4. 总 ID 空间严格为 57；特殊 ID、基础字符和合并片段全部计入预算。
5. 硬 AST-BPE 与软 AST-BPE 使用相同的 57-ID 容量预算。
6. 不以 UNK、替换、忽略或丢弃字符处理未覆盖输入；覆盖检查失败即停止该运行并报告。

作者词表的 ID 语义继续遵循作者字典。两个新分词器的特殊 ID 单独明确
编号并计入 57；不要求不同编码方案的同一个数值 ID 表示同一片段。
不得通过改变网络宽度、深度或输出掩码来隐藏词表未达到预算的问题。

## 共同控制

- 同一份 GRE 内容、目标方程排除规则、增强结果、原始样本顺序和批量。
- 分词器词表只从当次允许的训练公式学习，不读取完整数学 benchmark。
- 作者的固定 GRE 符号目录属于公开接口；目录包含一个基本项，不等于训练过由它构成的完整目标方程。
- 同一主干、相同初始化控制、优化器、学习率、epoch 和梯度裁剪。
- 位置嵌入容量如因序列展开需要适配，三组统一容量，并核对总参数量。
- 主实验沿用共同的 GRE 科学动作与 SAT 约束接口；修改生成策略的实验另行分组，不能同时计入纯编码方式比较。
- 同一观测数据、噪声、替代网络、元数据、候选数量、奖励、继续训练与 PINN 流程。
- 报告序列长度、实际 token 工作量与时间；相同 epoch 并不等于相同计算成本。

## 下一次实施顺序

1. 实现 GRE 字符字母表与 57-ID 容量管理，保留硬／软 AST 两种原有算法主线。
2. 检查训练输入及合法 GRE 输出目录的字符覆盖、往返、特殊 ID 和模型矩阵形状。
3. 至少四轮审查数据、模型、SAT 适配、训练更新、奖励及评估一致性。
4. 本地 smoke 与独立重复；如实记录数值失败。
5. 生成独立的 57-ID 云端运行包，通过解压验证后再用于 GPU 正式实验。

1,024-ID 包 `eqgpt_tokenizer_cloud_20261016.zip` 及其已有审查记录对应此前
版本，不能作为本协议已经实施或通过验证的证据。
