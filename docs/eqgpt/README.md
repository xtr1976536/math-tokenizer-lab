# EqGPT：三种分词器的公平下游实验

本轮按 [最终执行计划](final_execution_plan.md)实施；该计划优先于下文保留的旧版实现记录。

当前第二轮主实验范围见 [当前范围](current_stage2_scope.md)，训练预算与学习率的文献依据见 [公平训练协议](literature/training_fairness_20261016.md)。

> GRE／57-ID 与容量、语料等消融暂缓。下文保留此前 GRE 适配版本的实现记录，

## 实验对象

按本轮确认，只使用 **EqGPT 作者架构**，不引入另一套 GPT-2 主干。

| 模型 | 分词器 | 输入嵌入／输出投影 | Transformer |
|---|---|---|---|
| EqGPT | 作者原始 GRE，57 个 ID | 57 × 768 | 作者 GPT 类 |
| EqGPT + AST-BPE | 标准硬 AST-BPE，1,024 个 ID | 1,024 × 768 | 相同作者 GPT 类 |
| EqGPT + 软 AST-BPE | 软结构代价与动态规划，1,024 个 ID | 1,024 × 768 | 相同作者 GPT 类 |

两种新词表均包含 3 个特殊 ID 与至多 1,021 个内容 ID。词表只从当次
排除目标方程后的作者训练集学习，不读取数学 benchmark 的公式。
主干维度保持为：6 层、8 头、768 维嵌入、2048 维前馈层、每头 K/V 维数 64。
作者类中的注意力、ReLU、层归一化、残差、输入嵌入和独立输出投影均保留。
三组全部随机初始化；没有预训练权重、嵌入迁移或参数冻结。

所有非词表参数从同一个随机主干状态复制。位置嵌入容量按最长 GRE
子词编码统一扩展，三组相同；搜索仍以作者的 50 个 GRE 位置为上限，
不按不同分词器的子词数改变搜索长度。KdV 的共同位置容量为 148。
词表变化带来的总参数量差异保留并记录，不通过改变隐藏维数补齐。
作者定义但未在 forward 中调用的 `dec_enc_attn` 子模块也原样保留。

## 分词器与科学约束采样的接口

作者的 GRE 项，例如 `ut`、`uxx`、`(uux)x`，是固定的科学动作。
作者采样限制“项／运算符交替”，并按空间、时间变量屏蔽动作。
这些动作不能与新的子词 ID 混为一谈。

新适配器将每个 GRE 动作的原始拼写加逗号编码为子词码字，例如
`uxx,`。词表在完整作者结构串上训练，调用编码器时保留 GRE 动作边界，
因此不允许跨两个 GRE 动作合并。这一约束对两种新分词器相同。
它是在作者搜索空间内比较子词编码，不是自由 LaTeX 方程生成任务。

每个候选动作的得分为其码字的自回归概率乘积，不做长度归一化。
共享前缀用 trie 合并计算。动作得分交回作者原始 `GPT.step`，由它执行
变量屏蔽、交替约束与 80/20 采样。原分词器仍直接使用作者单 ID 概率。
生成的 GRE 动作原样交给作者奖励与 PINN，三组候选空间完全相同。

## 数据与训练设置

作者手册文件实际包含 221 行 PDE 结构。每个待发现目标及其交换项／
乘积等价形式在训练前排除，然后调用作者原始 32 倍增强。
例如 KdV 排除后有 220 行、7,040 条增强序列；三组使用同一列表与顺序。
每个新分词器在该列表上独立学习词表。目标数据只进入共同替代网络和
发现评测，不进入分词器或生成模型的词表训练。

正式设置：

- 生成模型：100 个 epoch，batch size 128，Adam，学习率 0.0001，梯度裁剪 1。
- 搜索：5 轮，每轮 400 个候选，按作者规则保留 10 个不同奖励的候选。
- 每轮继续训练：5 个 epoch，Adam，学习率 0.00001，同一模型与优化器绑定。
- 候选最大长度：沿用作者 `while len(sentence) < max_pos - 1`，`max_pos=50`。
- 替代网络：作者 5 层、每层 50 神经元，使用该案例指定的 Sin 或 Rational 激活。
- 替代网络：按公开代码运行 50,000 次更新，每 500 次保存并选择最低验证误差。
- PINN：作者原始前 3 候选、500 次更新，数据损失权重 1、PDE 损失权重 0.01。
- 数据、噪声、替代网络、元数据、PINN 训练／验证点均在三组之间配对并保存哈希。
- 正式种子为 525、526、527；每个案例／种子内三组严格配对。

作者论文称替代网络可提前停止，而固定公开代码没有这一分支；本包采用
公开代码的 50,000 次更新，不加入自行设计的早停。

## 本轮运行范围

`clean` 预设包含 10 个标准／复合 PDE 与圆盘 Poisson，共 11 个案例：
KdV、Burgers、Wave、Chaffee–Infante、Klein–Gordon、Allen–Cahn、
Convection–diffusion、PDE divide、Eq. 6.2.12、PDE compound、圆盘 Poisson。
前 10 个案例使用 10,000 个观测点；圆盘 Poisson 使用论文的 30,000 个点。
每个案例三个种子，每个种子三种模型，共 **99 次正式模型训练与发现**。

`noise` 预设在 KdV 上使用 0%、10%、20%、30%、40%、50% 的作者高斯噪声，
三个种子、三种模型，共 54 次。噪声按作者公开脚本
`(noise_level/100) * std(u) * randn(...)` 加到同一份原始解上。
两个预设的 KdV 无噪声设置重合，结果汇总时不重复计数。

笑脸区域也已做三组流程 smoke。EITech 虽能执行，但其常数项处理在作者
公开脚本中存在名称不一致，未纳入正式预设。二维 Burgers、H 形膜及
三维 shuttle 数据已下载并验签，但公开脚本的 PINN 数据格式或坐标绑定
还需对齐，因此不宣称已完成这些案例的端到端复现。
原文的真实水波／其他外部研究数据也不属于本包的 11 个案例。

## 作者发布版本中发现的问题

已统一修复三组运行所必需的执行与控制问题：

1. `surrogate_model.py` 存在空的 `Left =`，导致整份文件无法解析；包装层补齐未使用的赋值。
2. Burgers 路径缺少 `/`，H／二维 Burgers 的路径缺少 `data/`；包装层修正资源路径。
3. `get_train_dataset(Equation_name)` 内部实际调用 `read_dataset()`，没有传入目标名；包装层预先提供相同的排除后公式列表。
4. 搜索脚本的优化器绑定 `model_Q`，训练时却创建另一个 `model`；包装层的 GPT 工厂返回同一实例，并检查每轮参数确实更新。
5. 圆盘 Poisson 元数据函数返回 2 个值，调用处解包 4 个；包装层改为 2 个。
6. CPU smoke 将 `.cuda()` 映射为 `.to(device)`，正式 CUDA 算法不变。

保留的作者行为：部分增强序列把 EOS 移到中间、重复奖励去重、重复数值列删除、
PINN 对前 3 候选依次更新同一网络。它们在三组中一致，不单独为某种分词器修正。
若候选在 PINN 上出现除零／SVD 不收敛，保留原候选和日志，标记为数值失败；
不修改公式、移动数据点、补采样或用后续候选替代。

因此，本包是**作者公开实现、列明共同修复后的配对实验**；它不等同于把
原仓库直接执行一遍，也不宣称复现了论文所有图表。

## 结果

脚本输出结构精确恢复、带冗余项恢复、失败、top-10 恢复、每轮奖励、
PINN 状态与可对齐时的系数相对误差，另存训练／搜索／PINN 时间。
报告保留所有种子，数值失败计入相应分母，smoke 不进入正式结果。
固定的真值来自作者公开数据说明和论文方程，不能按生成结果修改。
结构恢复按无系数的 GRE 项比较，并展开明确的 Laplace 表示；系数误差单独
报告。该判据不把两个符号差异很大的式子交由任意阈值判作同一方程。

## 云端执行

建议 Linux、Python 3.11、RTX 4090／4090D 24GB、至少 32GB 主存。
保留作者 PyTorch 2.3.1 与 CUDA 12.1 环境，优先用 Ada／Ampere GPU。
不要在此固定环境下选择需要较新 PyTorch 支持的 RTX 5090。

```bash
bash scripts/eqgpt/install_cloud.sh
source .venv-eqgpt/bin/activate
export PYTHONPATH="$PWD/src"
python scripts/eqgpt/run_experiment.py --smoke --device cpu --output /tmp/eqgpt_check
python scripts/eqgpt/preflight.py --require-cuda
python scripts/eqgpt/run_suite.py --preset clean --output /workspace/eqgpt_results
python scripts/eqgpt/collect_results.py /workspace/eqgpt_results
```

正式任务要求显式 `--device cuda`，不自动回退 CPU、不付费创建实例。
`run_suite.py --plan-only` 只显示任务列表。已完成任务保持原样并跳过；
不覆盖未完成目录。结果目录应放持久数据盘，启动和停止云实例由用户控制。
