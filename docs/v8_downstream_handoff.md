# 下游实验交接：固定分词器，尚未执行任务训练

最终入口为`math_tokenizer.final_models.load_final`，检查点与角色来自`models/final_intrinsic/registry.json`。v6的`load_current`仅保留历史复现兼容，不作为这轮生产默认。生产训练路线中没有隐含RL更新或搜索；历史RL诊断需要明确设置`include_diagnostics=True`。

核心名单在v8新测试评分前冻结，标准角色共8个：AST参数边界路径、原版硬AST、同原子原版BPE、原版byte BPE、SentencePiece Unigram、Qwen2.5、Llama 3、o200k。数学/传统方法同时保存1024/2048预算和broad/specialized场景；常规下游先使用broad，不允许根据下游测试挑选specialized或某个训练seed。随机训练候选的部署seed固定17。

两个必要结构消融是AST两级长度优先路径与作者PathPiece，用于判断结构边界代价本身是否带来下游收益。父v5、终端RL、随机搜索、CEM及关闭更新仅作学习机制诊断，RL是否进入核心依预先登记的开发门槛。Qwen3、DeepSeek-V3、Phi-4、Mistral-Nemo、GPT-2、cl100k保留为扩展通用参考，本征结果已完整评测。

原版硬AST核心候选的词表与新分支不同，所以它比较的是完整分词系统，不独立归因于硬结构。严格结构因果对照另使用正式实验注册表中的`hard_tree_atomic_vocab`、`lexical_shortest`与`official_atomic_bpe`，三者共享相同词表。数学原子BPE是原版算法加明确词法先验，不称原创RL方法。

下游开始前须固定任务、模型及训练预算，不能把成熟tokenizer不同词表的embedding/softmax成本隐藏在“相同架构”描述里。建议区分两种报告：相同数学词表容量的因果对照；保留通用词表原样的实际部署参考。成熟tokenizer本身不带其预训练语言模型的权重收益。

共同输入应是相同原始训练/验证/测试样本及来源划分。按固定原始字节或样本预算计训练资料，同时报告token量、总参数、embedding参数、训练FLOPs、时间、上下文原始字节覆盖及截断比例。不能一组按token训练、另一组按字节训练后直接称公平；若固定token上下文使原文覆盖不同，应作为明确的实验条件记录。

所有组执行相同BOS/EOS/PAD处理策略，新加特殊ID计入实际容量与参数。控制字符串规范化和空白处理，确保decode原文规则一致。独立分词器原有无损接口不应被语言模型包装静默改写。任务评估共享原始测试样本，禁止按模型可编码性或长度单独删除样本。

下游的超参数只在共同验证范围内选择、分配相同搜索预算，固定随机种子，报告失败及方差。这份文档只提供交接约束，未假装任务或架构已经选定，也没有执行任何下游模型训练。

v8最终实验报告和`verification.json`列出源码结构代理、单机测速、未知成熟模型预训练污染、领域覆盖及未完成专家金标准等限制。后续不得把这些限制省略成“已证明数学语义最优”。
