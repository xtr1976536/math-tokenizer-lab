# 首版结果解读

首版共有 1,713 条公式，267 个实际有数据的文档／公式家族；train/dev/test=1,026/281/406。测试集含 analysis 130、logic 120、combinatorics 120、PDE 32、linear algebra 4。其余领域在本版没有独立 test 组，不能对这些领域报告测试性能。OpenAI 长稿件每文档最多120条使公式数量较均衡，但分组数量仍少。来源、领域和长度存在混杂；这些数据不是“人工来源与 AI 来源因果比较”的实验。

## 压缩

384 预算，普通 byte BPE 为 14.377 token/公式；HF 官方 ByteLevel BPE 也为 14.377，确认基准与自研普通 BPE 的实现行为在该数据上相吻合。RL-BPE 三种子分别 14.638/14.330/14.468，平均14.479；一个种子略短、两个略长。512预算，byte BPE为12.616，RL-BPE平均12.532（约0.66%缩短）。多数条件区间跨0，一个512种子的组bootstrap区间仅略低于0，不能据此声称稳定RL增益。

AST-BPE 的全测试 token 长度 384预算17.537、512预算16.818，明显长于 byte BPE。主要原因是 208/406 条公式没有被受限 AST 解析，整式回退为 byte；这些公式平均25.822个字节，也就是结构方法的25.822 token。相同子集的 byte BPE仅19.875（384）/17.572（512）。这比增加合并预算更值得优先修复。

在198条可解析公式上，种子17的 AST-BPE 为8.833（384）/7.359（512），byte BPE为8.601/7.409。512配置的这一小差异不支持强结论，但是说明 AST 方法的整体劣势不能简单归因于所有可解析表达式都压缩得差。解析失败与成功是按同一 parser 预定的子群，不是按模型成绩筛选。

32条PDE测试子群，种子17的 AST-BPE为15.062（384）/12.500（512），byte BPE为16.344/13.719。该子群以人工整理的重复导数结构为主，结构词表与它的匹配有局部优势，但规模和独立来源不足，不代表一般 PDE 或真实论文公式的效果。必须补足完整系数方程与独立 PDE 论文再验证。

RL-AST-BPE 全测试也未优于 AST-BPE：384预算平均17.644，512平均16.843。压缩奖励、top-24候选和线性策略较简单，可能被内部留出样本相关性与表示覆盖限制。需要等fit数据的no-RL控制、随机策略、greedy reward、长期收益等进一步消融，不能把目前有限增益归因于强化学习优势。

## 结构与速度

AST支持的198条公式上，AST方法没有部分跨切AST子树的token。byte BPE种子17的跨切比例约15.38%（384）。这个指标按源跨度的层状兼容规则定义，并不验证命令原子性、数学等价性或推理正确性；纯UTF-8字节本身也零跨切，故必须同时看压缩。

linked-list/ranked-heap 编码与保留的逐规则扫描参考实现，在18个模型、406条测试公式、Unicode随机用例上全部给出相同token ID。机器实测约7.7倍结构方法提速、13倍字节方法提速。这个比值只针对本机、当前词表和小公式；不代表对Rust/C++基准的优势。HF/SentencePiece 原生实现仍更快。
